# Повторная генерация временных паролей сотрудников

## Что делает патч
- Добавляет в админ-панель кнопку «Временные пароли».
- Позволяет выбрать конкретных сотрудников с привязанной учётной записью.
- На сервере генерирует индивидуальные криптографически случайные пароли.
- Обновляет пароль существующего пользователя Supabase Auth через Admin API.
- Возвращает временные пароли только в ответе текущего запроса; интерфейс формирует CSV для однократного скачивания.
- Не меняет профили, табельные номера, роли, подразделения и назначения обучения.

## Критически важно
Сброс пароля немедленно делает прежний пароль выбранного сотрудника недействительным. Выбирайте только тех, кому действительно нужно восстановить доступ. Не выбирайте всех 150 сотрудников без необходимости.

Пароли не записываются в таблицы приложения и не логируются сервером. CSV содержит секретные данные: храните его локально в защищённом месте, раздавайте индивидуально и удалите после безопасной передачи. Не коммитьте CSV в GitHub и не отправляйте общим чатом.

## Установка
1. Сделайте резервную копию текущего `src/components/AdminView.tsx`.
2. Скопируйте `src/components/AdminView.tsx` из архива в репозиторий, заменив файл.
3. Добавьте новый файл `src/app/api/admin/employees/reset-passwords/route.ts`.
4. Убедитесь, что `SUPABASE_SERVICE_ROLE_KEY` задан в Amvera как секрет только на этапе «Запуск». Не добавляйте его в `NEXT_PUBLIC_*` и не помещайте в GitHub.
5. Commit в `main` и дождитесь успешной сборки Amvera.

SQL-миграция не требуется.

## Проверка
1. Откройте Админ-панель → Сотрудники и доступы.
2. Нажмите «Временные пароли».
3. Выберите одного тестового сотрудника, которому разрешено сменить пароль.
4. Нажмите «Сбросить и скачать CSV».
5. Проверьте вход с новым паролем.
6. После успешной проверки используйте функцию только для конкретных сотрудников, которым нужен сброс.

## Ограничения этого патча
- Требуется, чтобы `profiles.auth_user_id` был заполнен.
- Неактивные/несвязанные Auth-профили пропускаются.
- Патч не реализует обязательную смену пароля при первом входе: временный пароль является обычным паролем до следующей смены пользователем.
- Патч не рассылает пароли по SMS/email; передача выполняется администратором.
- Не запускать массовый сброс всем сотрудникам без подтверждённой необходимости.
