# Bionit — массовый импорт сотрудников (патч)

## Состав
- `src/app/api/admin/employees/bulk/route.ts` — серверный endpoint массового создания Auth-пользователей и профилей.
- `src/components/AdminView.tsx` — кнопка и окно массового импорта в админ-панели; поле телефона не показывается и не требуется.
- `import-data/` — сюда администратор локально кладёт JSON-реестр перед импортом. Персональные данные не коммитить в GitHub.

## Требования
1. В Amvera добавить `SUPABASE_SERVICE_ROLE_KEY` как секрет только на этапе **Запуск**. Никогда не использовать его в `NEXT_PUBLIC_*`.
2. Убедиться, что в Supabase работает Auth-триггер `handle_new_auth_user`, создающий `public.profiles` из `user_metadata` (как в текущей реализации одиночного создания сотрудника).
3. Названия подразделений в JSON должны совпадать с активными `departments.name` компании. Несовпавшие записи получат статус `error`, другие строки продолжат импортироваться.
4. Массовый импорт создаёт только роль `employee`. Роли HR/manager/admin назначаются отдельно через штатное управление доступом.

## Установка
Скопировать файлы из архива в корень репозитория GitHub, сохранив пути, заменить существующий `src/components/AdminView.tsx`, добавить новый route. Commit в `main`; дождаться сборки Amvera.

## Импорт
1. Откройте Админ-панель → Сотрудники и доступы → Массовый импорт.
2. Выберите JSON с объектом вида `{ "employees": [...] }`.
3. Сначала подготовьте файл с одной тестовой записью и выполните тестовый импорт.
4. Проверьте появление пользователя в списке, возможность входа и профиль в Supabase.
5. Затем загрузите полный JSON-реестр. Повторные табельные номера пропускаются без перезаписи.
6. После завершения браузер скачает CSV с временными паролями. Сохраните его в защищённом месте и передавайте сотрудникам индивидуально. CSV не хранить в GitHub, общей папке или открытом чате.

## Безопасность и ограничения
- Максимум 200 строк на один запрос.
- Табельные номера проверяются на дубли внутри файла и в `profiles`.
- Уже существующие профили не перезаписываются.
- При ошибке создания конкретной учётной записи выполняется попытка удалить созданные для неё Auth/profile записи.
- Пароли генерируются на сервере криптографическим генератором и возвращаются администратору только один раз в ответе импорта. База пароли в открытом виде не хранит.
- Этот патч пока **не реализует принудительный экран смены пароля при первом входе**. Временные пароли следует раздать безопасно; обязательную смену пароля добавим отдельным согласованным изменением auth-flow.
- Не загружайте персональный JSON в GitHub. Используйте локальный файл на компьютере.

## Проверки после установки
- одиночное создание сотрудника без телефона;
- импорт одной тестовой записи;
- повторный импорт той же записи (должна быть пропущена);
- импорт полной выборки;
- проверка подразделения, табельного номера, должности и роли;
- проверка входа по табельному номеру и временному паролю.
